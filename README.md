# Beads Studio · 拼豆工作流工作室

纯浏览器运行的拼豆设计工具，把「规范化 → 优化颜色 → 转拼豆图纸」串成一条完整工作流。
没有后端、没有上传，所有计算都在本地完成。

---

## 三个阶段

### ① 规范化 — 任意图片 → 一个像素 = 一颗豆

同一件事提供三种输入方式，按素材类型选：

| 方式 | 适合什么素材 | 原理 |
| --- | --- | --- |
| **自动识别** | 像素画截图、被放大的像素图、正对着拍的拼豆板 | 灰度 → 方向投影 → FFT 自相关 → 峰列基频拟合 → 相位对齐 → 按格取样 |
| **四角变换** | 斜着拍、有透视、有背景杂物的照片 | 手动拖 4 个角点，双线性插值逐格取样 |
| **直接 1:1** | 已经画好的 1 像素 = 1 颗豆的设计稿 | 原样作为网格；若是整数倍放大的稿子会自动探测倍数并压回 |

**自动识别**不是简单地数格子：它用自相关找出真实存在的峰列，再用「峰 ≈ k × 周期」的栅格拟合给候选打分，
评分同时看对齐峰数、对齐误差、谐波连续性和空缺情况。这样能避免把真实的 `25/50/75/100/125/150`
错压成 `50/100/150`（即把基频认成 2 倍周期）。

**直接 1:1** 的倍数探测用了一个 O(w·h) 的技巧：先算「哪些相邻列 / 行存在差异」，
再检查所有非 N 倍数位置是否都没有差异 —— 等价于「N×N 块内颜色一致」，比逐块比较快得多。

### ② 优化颜色 — 从色号库里挑出最终配色

优化目标直接取自 **① 的规范化结果**：把网格里每个颜色按出现次数加权，作为目标色集。
然后用模拟退火（SA）从色号库中选出 K 个色号，使整幅图的加权平均 ΔE（或最大 ΔE）最小。

和常见实现的区别是**最近色距离做了增量维护**：交换一个颜色时，只有「最近色正好是被移除的那一个」
的目标需要重算，其余目标只需检查新颜色是否更近。语义完全等价，但每一步从 O(目标数 × 色数)
降到接近 O(目标数)，所以几千个目标色也跑得动。

其他要点：

- **贪心最远点初始解**（k-center）代替随机初始解，结果明显更稳
- **退火后贪心精修**，把每个已选色再逐个试换一遍
- **固定黑白**（MARD `H02` / `H07`）默认锁定，符合拼豆实际习惯
- **相同种子 + 相同设置 = 相同结果**，方便复现和对比

目标来源也可以切换成「全量色谱」，用来先定一套通用色板。

**候选色筛选**：「选择候选色」会打开一个按 MARD 系列（A/B/C/D/E/F/G/H…）分组的弹窗，
逐色勾选谁能参与优化，也可以整组一键开关 / 全局全选、反选。不筛选时整本色号库都可选。
候选色越多可选空间越大，但搜索越慢 —— 通常圈定几个系列就够。

### ③ 转拼豆图纸 — 量化 → 出图 → 用料清单

- 每格吸附到色板里最接近的色号（Lab ΔE，或复刻旧工具的 0.3/0.59/0.11 加权 RGB）
- 可选 Floyd–Steinberg 误差扩散抖动
- **色板来源**可选：优化结果 / 色号库 / 基础24色 / 基础48色 / 自定义。
  从「优化颜色」套用结果进来时默认就是**优化结果**；切到别的来源再切回来，这套结果原样还在
  （优化结果单独存在 optimizedPalette 里，不会被别的来源覆盖）。还没跑过优化就选「优化结果」会被拦下并提醒
- 默认就是**带色号的方格图纸**，另可切到**珠子**样式（圆形 + 高光，模拟真实观感）
- 网格线分两级：**每格一条细线**，**每 10 格一条粗线**（间隔可调），数格子不用再一个个数
- 可叠加行列标尺、自定义背景色；色号文字会根据底色自动切黑/白保证可读
- 自动统计用料清单（色号 / HEX / 数量 / 占比），一键导出

**图纸用 SVG 绘制，不是 canvas。** 图纸本质是矢量内容，用 canvas 渲染再靠 CSS 放大一定会糊，
所以预览、全屏看图和导出都走同一份 SVG：屏幕缩放是重新绘制，导出 PNG 也是按倍数重新光栅化
（1× / 2× / 4× / 8×），放到多大都清晰。也可以直接导出 `.svg`。

导出：图纸 SVG、图纸 PNG（最高 8×）、1:1 像素图 PNG、用料 CSV、色号 / HEX / JSON 列表。

另有**全屏预览**：滚轮缩放 + 拖动平移，全屏期间申请 Wake Lock 让屏幕保持常亮，方便对着屏幕一颗颗摆。

## 标签页与自动保存

- **标签页**：顶栏是浏览器式的项目标签。每个标签是一个独立项目（各自的图、网格、色板、配色结果），
  点击切换、右侧 × 关闭、双击名字改名、＋ 新建并打开图片。
  拖入图片或粘贴截图也会开新标签页。
- **自动保存**：停止编辑约 1 秒后自动写进浏览器 localStorage，关页面时再补一次。
- **重启恢复**：下次打开会自动装回上次开着的标签页与编辑进度。
- **最近项目**：顶栏最右边的按钮会打开一个弹窗，列出本机存档（缩略图 / 网格尺寸 / 保存时间 / 占用空间），
  可以打开、删除，也可以一键关掉自动保存。
- **导出 / 导入文件**：需要跨设备或留底时，用顶栏的「导出文件 / 导入文件」走 JSON 文件，
  和自动保存互不影响。

localStorage 通常只有 5MB，原图 PNG 很容易撑爆，所以存不下时按这个顺序退让：
先丢掉原图只存网格与配色（界面会提示），再淘汰最旧的其它项目，最后才报错 —— 不会静默丢数据。

测试：

```bash
npm test           # 核心算法自检（73 项，走 Node，无需浏览器）
npm run test:ui    # 运行时冒烟测试（104 项，jsdom 里真正启动 React 应用跑完整流程）
npm run test:all   # 两个都跑
```

`npm test` 会用一张「12×10 像素画被 8 倍放大成 96×80」的合成图验证整条链路：
周期是否检测到 8、重采样后是否 12×10、逐格颜色是否与原像素画完全一致、
四角变换能否还原、量化结果是否全部落在色板内、优化结果是否优于随机基准且可复现。

`npm run test:ui` 在 jsdom 里真正挂载 `<App />`，注入一张合成图后走完
「载入图片 → 自动识别 → 优化配色 → 应用到图纸 → 切换抖动 / 匹配算法」的全流程，
并验证图纸确实是挂在 DOM 上的 SVG、自动保存写进了 localStorage、标签页切换/关闭不丢状态、
关闭后再从「最近项目」打开能完整还原、以及重启后会话能恢复；
也覆盖了「切到别的色板来源再切回优化结果，颜色必须原样还在」和候选色筛选真的收窄了优化范围。

另外两个可选的核对工具：

```bash
npm run sample:svg   # 生成一张示例图纸 SVG，直接用浏览器打开看样式（无额外依赖）
npm i -D sharp && npm run verify:svg
                     # 把图纸光栅化后逐像素核对：细线暗度、粗线宽度、填色、色号对比度
```

## 技术栈

Vite + React 19 + TypeScript（`strict` + `erasableSyntaxOnly`）+ zustand。
没有 UI 框架，样式是手写 CSS（暗色主题）。

核心算法与 DOM 解耦，全部放在 `src/core/`，只操作朴素的
`{ width, height, data: Uint8ClampedArray }`，所以同一套代码既能在浏览器里跑，也能在 Node 里直接测。

```
src/
  core/
    fft.ts          迭代式 FFT + 自相关
    regularize.ts   周期检测、相位对齐、按格重采样
    warp.ts         四角变换（双线性）
    direct.ts       1:1 输入：放大倍数探测与块压缩
    palette.ts      色号库、色号体系、最近色查找
    quantize.ts     量化 + Floyd–Steinberg + 用量统计
    optimize.ts     模拟退火配色优化（增量最近色）
    svg.ts          图纸矢量绘制（方格 / 珠子、两级网格线、色号、标尺、导出入 PNG）
    render.ts       像素数据的最近邻绘制（源图 / 1:1 网格预览）
    export.ts       PNG / CSV / JSON / 项目存档
    color.ts        sRGB↔Lab、ΔE、各种取平均方式
    storage.ts      localStorage 存档（索引 + 正文 + 会话，含配额退让策略）
  components/       三个阶段 + 全屏预览 + UI 原子件
  store/studio.ts   全局状态、标签页、自动保存与工作流编排
```

## 关于色号库

`src/data/beadColors.ts` 由原 `beads-color-sampler.html` 内嵌的数据提取而来，
共 **291 个颜色**，每个颜色带 5 套品牌色号：MARD / COCO / 漫漫 / 盼盼 / 咪小窝。
（`src/data/beadColors.json` 是同一份数据的原始 JSON 抽取结果，`beadColors.ts` 由它生成，供应用直接 import。）

默认只把 MARD 首位为 **A–H 的 206 色**作为候选（与原工具一致），
可在「优化颜色」里勾选「包含扩展色号」把 M / P / Q / R / T / Y / ZG 系列也纳入。

内置精简色板（都用 MARD 色号定义，`src/core/palette.ts`）：

- **基础 24 色**：`B03 B05 B08 C03 C05 C08 D09 D06 D07 E02 E04 F05 G01 G05 G07 A04 A06 A07 H01 H02 H03 H04 H05 H07`
- **基础 48 色**：24 色 + `C02 C10 C11 B12 C13 C06 C07 D03 D19 D18 D21 D15 E08 E03 D13 E07 A13 A10 F13 F08 A11 G09 G13 G08`

> 旧「拼豆工具箱」那套 31 色其实是 **wplace** 的调色板，不是拼豆颜色，所以已经从界面隐藏，
> 但数据与生成函数仍然保留在代码里，命名为 `WPLACE_COLORS` / `buildWplacePalette()`。

> 注意：不同品牌会重号（COCO 的 `B02` 和 MARD 的 `B02` 是两个颜色）。
> 粘贴色号解析时会优先按当前选定的色号体系匹配，其余体系只在没有歧义时兜底。

## 与三个原始 HTML 工具的关系

仓库根目录保留了最初的三个单文件工具，Beads Studio 是把它们合并、打通并补齐的结果：

| 原始文件 | 在 Beads Studio 中的位置 |
| --- | --- |
| `pixelart-regualizer.html` | ① 规范化的「自动识别」 |
| `fuse-beads-tool.html` | ① 规范化的「四角变换」+ ③ 的珠子预览与色板管理 |
| `beads-color-sampler.html` | ② 优化颜色（优化目标改为直接读规范化结果） |

相比原工具的主要改进：

- 三个阶段连成一条流水线，结果直接传递，不用手动导出再导入
- 清掉了原文件里重复的字段定义与重复的事件绑定
- 优化器改为增量维护最近色，速度提升到可以处理几千个目标色
- 用贪心初始解 + 贪心精修提升配色质量
- 补上原工具缺失的部分：固定色号、用料清单、图纸导出、项目存档、全屏看图

## 项目存档

「保存项目」会导出一个 JSON：

```jsonc
{
  "app": "beads-studio",
  "version": 1,
  "savedAt": "...",
  "grid": { "width": 48, "height": 32, "data": "<base64 RGBA>" },
  "paletteHex": ["#FEFFFF", "#000000", "..."],
  "settings": { "codeSystem": "MARD", "quantizeOptions": {}, "renderOptions": {}, "...": {} }
}
```

「读取项目」可以还原网格、色板与所有设置（不含原始图片，图片需要另外重新打开）。
